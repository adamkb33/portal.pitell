## 3. Backend: refresh-token hardening (from the auth review)

The refresh flow works end to end (6/6 `auth-refresh` tests pass). Remaining issues, most serious first:

- [x] **`TokenService.refresh` doesn't check company membership.** `refresh` now runs the same check as `signIn`
      before rotating, so a refused refresh leaves the token unused. A user removed from a company is refused too.
      Tests: `TokenServiceIntegrationTest` (3 new) and `token-refresh.spec.ts` "cannot be used to get into a company…".
- [x] **No reuse detection.** A replaced refresh token that comes back more than 30 seconds after it was replaced
      revokes every refresh token of the user (in its own transaction, so the refusal can't roll it back).
- [x] **Concurrent refreshes race.** Within those 30 seconds, and while its replacement is still live, a replaced token
      gets tokens of its own instead of failing. Tests: `TokenServiceIntegrationTest` (3 new) and the updated
      `token-refresh.spec.ts` rotation test.
- [ ] **Expired-token revoke is rolled back.** `revoke()` then throw inside `@Transactional` does not persist.
- [ ] **Errors are inline strings.** `IllegalStateException`/`EntityNotFoundException` in `refresh` should use
      `ApiMessageId` + `BusinessLogicException` so the client gets a clean 401.
- [ ] **`POST /auth/sign-out` takes `userId` from the body.** Confirm it is authenticated and derive the id from the token.
- [ ] Pin the status code of a replayed/garbage refresh token in the `auth-refresh` API tests once the above is done.

## 4. Portal: refresh handling gaps

- [x] Access cookie now lives as long as the refresh cookie, and `getCompanyIdFromToken` ignores expiry, so a refresh
      keeps the company context.
- [ ] Only the root loader refreshes. Child loaders, actions and resource routes (`withAuth`) read the cookie directly
      and can send an expired token on the first request after expiry. Refresh centrally or retry once on 401.
- [ ] A transient refresh failure (non-auth error) clears both cookies and signs the user out. Only clear on a real
      401/invalid-token response.
