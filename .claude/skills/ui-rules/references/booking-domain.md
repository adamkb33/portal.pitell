# Booking domain map — the blueprint

Booking (`/company/booking/*`) is the first domain rewritten on the app-wide rules in `../SKILL.md` (page types, areas, page top, creating, forms, toasts, rows). When it's done, it is the worked example the other domains copy: start the next domain's map by copying this file's structure (areas table, overview, page-by-page table) and filling it in for that domain.

This file holds only what is specific to booking. The rules themselves live in `SKILL.md`; don't restate them here.

The user approved this map on 2026-11-07 from a sketch of the whole domain. The customer-facing booking flow (`/booking/public/*`) is not part of it; it has its own spec (`app/routes/booking/public/_design.spec.md`) and themeable `booking-*` tokens.

## The domain's Oversikt (the Booking page)

- Key destinations first, side by side: Kalender (teal, "n avtaler i dag") and Timebestillinger (cyan, "n kommende"), full-colour cards. The numbers are the appointment list's own totals (today in Oslo; from now on), so a card matches the page it opens.
- Card 1, everyone: Tilgjengelighet, Bookingprofil, Statistikk ("Kalender og timer" is shown as the two key cards instead of a row).
- Card 2, admins only, strip "Oppsett" with "Admin" on the right: Tjenester, Lojalitetsprogram.
- Row lines: "Arbeidsdagen", "Bookbar tid og fravær", "Det kundene ser", "Omsetning og avtaler", real counts for Tjenester ("4 tjenester · 3 grupper"), the real loyalty state for Lojalitetsprogram ("Hvert 5. besøk er gratis", or "Av").
- The separate Oppsett page (`/company/booking/admin`) goes away: its route redirects here.

## Booking-specific notes

- Appointment rows everywhere use `AppointmentListRow` (`app/routes/company/booking/appointments/_components/appointment.list-row.tsx`), including Kalender's day list.
- Every area switch is `AreaSwitch` (`app/routes/_components/area-switch.tsx`, built on `SegmentedLinks` in `~/ui`); Kommende | Tidligere is `PeriodSwitch` on the same control. Lists use `ListRow` / `ListStrip` / `ListEmpty` from `~/ui`; Tjenester, Grupper and the overview still hand-write theirs and should move to them when touched.
- Bookbar tid only stores the part of a range that falls outside the profile's working hours (backend `ScheduleAvailabilityService.createAvailability`), so 15:00–19:00 on a day that ends at 17:00 is saved as 17:00–19:00.
- Bookbar tid's inline "Legg til tid" form moves to its own create page (needs a create route under `company/booking/schedule/availabilities`).
- Up (the header ‹ / breadcrumb) follows the map, not the URL: Bookbar tid, Tjenester, Grupper and Lojalitetsprogram go up to Booking; Ny bookbar tid to Bookbar tid; Last opp bilde to its Timebestilling. The appointment detail goes up to Timebestillinger, also when opened from Kalender (the browser's back still returns to Kalender).
- Deleting a service group deletes its services (backend `AdminDeleteServiceGroupUseCase`); the confirm dialog says so.

- 2026-11-07 – Customer preview row ("Se profilen som kunde") is deferred until its own preview is designed; do not send it into the public booking flow. Summary edit rows now open the separate edit routes decided below.

- 2026-11-07 – Each Bookingprofil section gets its own Skjema route: Profil (description and photo), Tjenester, Arbeidstider. Each saves only its section, returns to Bookingprofil with a toast, and goes up to Bookingprofil. Sketch each before implementation. This replaces the combined edit form.

- 2026-11-07 – The separate profile edit pages keep the arrow-only phone header link (accessible name "Tilbake til Bookingprofil"); no visible back-link text. Desktop uses its clickable Bookingprofil breadcrumb.

- 2026-11-08 – Built the three separate profile forms with the shared Lagre bar. Each save preserves the other sections. Work-hours saves replace the selected days atomically (including an empty week); this required fixing `BookingProfileService` in the sibling backend. Photo requests normalize the generated image discriminator to Jackson’s `UPLOAD` / `DELETE` wire values.

### Bookingprofil delivery record (2026-11-08)

- **Design:** The summary follows [Summary page](../../page-sketch/references/patterns.md#summary-page-oversikt-of-one-thing); the three edit routes follow [Edit / create page](../../page-sketch/references/patterns.md#edit--create-page). The pink Bookingprofil tone, neutral cards, Inter typography, touch sizes and minimal Norwegian labels follow [design language](../../page-sketch/references/design-language.md). Phone and desktop up navigation follows [Page top](../../page-sketch/references/patterns.md#page-top-company).
- **Practices:** Each section has its own route and save action; forms use `CompanyFormPageTemplate`, `formPage` handles, the shared Lagre bar and flash toast from [ui-rules](../SKILL.md#2-form-pages). Route metadata maps each edit page up to Bookingprofil. No in-page back link or customer-preview shortcut was added.
- **Delivered:** Bookingprofil summary plus Profil, Tjenester and Arbeidstider edit routes; create-profile flow; section saves that preserve unrelated fields; removal of selected workdays, including clearing the whole week; photo upload and removal. The related implementation is in `app/routes/company/booking/profile/`; the sibling backend fix is [`BookingProfileService.kt`](../../../../pitell/src/services/booking-service/src/main/kotlin/no/pitell/booking_service/application/profiles/services/BookingProfileService.kt).
- **Verification:** `tests/e2e/booking-profile.spec.ts` covers create, edit, validation, persistence, cross-section preservation, phone header navigation and desktop breadcrumbs at 375px and 1280px. The profile suite passed (8 tests); typecheck, 334 Vitest tests and formatting checks passed.
